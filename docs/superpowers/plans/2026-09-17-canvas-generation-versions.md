# 画布提示词与图片版本迭代实施计划

> 执行方式：使用 executing-plans 在当前会话按任务执行。用户已确认设计并授权当前分支实施；中文界面和文档，不自动提交、不触发真实计费生图。

**目标：** 从生成步骤卡片编辑提示词，以明确的上一级图片版本重新生成，保存提示词及图片历史，选择图片版本时同步显示对应生成快照。

**设计依据：** 2026-09-17 用户已确认的四条规则：上游源图重新生成、提示词与结果关联版本、图片版本切换、历史脉络保持准确。

**架构：** 为每个原始生成步骤建立画布版本记录，以原有步骤 ID 为稳定标识；一个版本冻结源图、约束、参数、提示词和输出顺序。独立应用服务通过现有图片 Provider 和资产／成品库接口生成，数据库原子认领防重复；前端把这些版本投影回原图片节点，不覆盖原资产。

**技术：** FastAPI、SQLAlchemy/PostgreSQL、Alembic、React、XYFlow。

## 约束

- 重新生成从该版本的上游图取输入；用户可以明确选择同一上游图片的其他版本，多源图保持数量和顺序。
- 风格、平台和真实性约束使用历史快照，只编辑模块提示词；白底图和修改图可编辑其任务提示词。
- 新版成功才替换对应当前图，失败保留旧图；同版本多张输出按固定槽位分别管理。
- 版本切换只更新展示与持久选择，不级联生成。被下游使用的旧图保留独立节点。
- 只有用户确认提交才调用 Provider。自动化验证使用假 Provider。

## 操作入口与当前边界

生成步骤卡片 → “修改提示词并生成” → 选择提示词版本和上游图片版本 → 编辑任务提示词 → 确认生成新版本。风格、平台和真实性约束沿用该版本快照。

生成成功后更新图片；图片节点的“图片版本”和右侧图片属性中的历史版本均可切换，选择持久保存。切换上游不自动更新下游，需打开下游步骤明确选取输入版本并再次确认生成。

当前一次迭代对应该步骤记录的全部输出位置；尚未做仅重试指定失败位置。当前模型与记录中的具体模型不符时拒绝提交，避免把另一模型的结果写成原模型版本。自动化均使用假 Provider，实际模型的出图效果及费用仍需用户手动验收。
