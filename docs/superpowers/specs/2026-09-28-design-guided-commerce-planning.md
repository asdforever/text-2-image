# 电商规划大师：设计知识接入与表达自由度设计

日期：2026-09-28。状态：供实施的设计草案；本次只编写设计和计划，未修改运行逻辑。

## 目标与范围

让主图、套图规划从「选择商品展示模块」转为「购买问题 → 真实信息/证据 → 视觉表达 → 商品出场方式 → 执行模块」。接入经过适配的设计知识，避免把高星 Skill 的工具指令、网页规则和特定审美偏好直接拼进系统提示词。

第一版贯通知识加载、规划输入输出、单图编译与前端任务表达。用户已明确旧任务无需兼容：只支持新任务，不建设旧字段回退、历史任务恢复/重试适配或数据迁移。沿用现有规划与生成调用，不新增模型调用阶段，不新增依赖；不在本次加入自动审图、自动重画、RAG、在线下载 Skill、自由 Agent、风格训练或新的图片渲染引擎。

## 已核实的现状

- `backend/app/application/module_planning_service.py` 实际请求包含内置规划 Skill 和 GPT Image 模板库；`designKnowledge` 目前仅写入 snapshot，没有进入大师实际请求。
- `backend/app/application/module_planning_v2.py` 已把设计知识传给单图编译器，支持 `productPresence=full/partial/detail/context/none`，但固定种子要求配色、光线均不得改变。
- 主图与套图都有独立 `taskId`，同一 `moduleId` 可以复用；应沿用这套身份机制及失败重试。
- 大师校验要求 moduleId 属于配置目录；更改默认目录不会自动修改已有工作区的不可变发布配置。
- 后端输出和前端 `src/lib/planning-master.ts` 都会把 compositionBrief 追加进模块参数；用户可以手动编辑这些参数，需要区分建议与手改要求。
- 大师请求没有 styleId/customStyle；前端规划指纹也不包含风格，当前可能恢复与现有风格不一致的规划。

证据与来源见 `research/design-skills-candidates-2026-09-28.md` 和 `research/github-ecommerce-image-workflows-2026-09-28.md`。

## 全局约束

- 商品事实、平台适用规则、用户明确要求优先于设计建议；创意不得编造参数、内部结构、认证、实测数据、承诺或人群适用结论。
- 不按商品品类写死版式，不规定每套必须有无产品图；商品出场方式应由信息表达决定。
- 主图最多 8 个任务，每个任务生成 1 张；沿用现有套图数量机制，不在此扩大限制。
- 第一版不增加模型调用阶段；知识加载完全离线，不增加运行时第三方依赖。
- 仅支持新任务；不实现旧任务兼容、迁移或清理。当前工作区配置继续服务新任务，不改写不可变发布版本。
- 不覆盖已有未提交改动，不修改数据库连接、并发配置、远端服务或项目素材。

## 1. 设计知识如何接入

新增应用自有 `commerce_design_v1` 知识包及加载器，复用现有风格库加载、校验、hash、快照模式。知识包包括：

| ID | 指导内容 | 主要来源 |
|---|---|---|
| commerce-core | 购买问题、事实证据、每图沟通目标、整套叙事 | 现有电商规划规范与已调研电商工作流 |
| visual-hierarchy | 视觉焦点、信息主次、标题与图形关系、系列共性与变化 | UI UX Pro Max banner-design、Impeccable |
| data-explanation | 参数含义、数字与图解关系、区分概念示意和实测图 | 对通用层级方法的电商适配 |
| usage-context | 用户活动、操作关系、需求情境、避免纯摆拍充当场景解释 | 对广告目标及叙事方法的电商适配 |

大师收到四份精简指导全文，总指导正文上限 6,000 个 Unicode 字符，另附现有模板目录；大师为每张图选择 1–2 个辅助 guide ID，核心规则常驻。单图编译读取核心规则及所选指南全文，无规划大师的手动新任务使用核心规则和 visual-hierarchy。自动规划的缺失或未知指南为无效响应，不提供历史兼容默认值。

来源清单记录仓库、固定 commit、文件路径、许可证与改写说明。MIT/Apache-2.0 复用保留相应版权和许可；改写规则与上游原文明确区分。去掉 HTML/CSS/CLI 操作、多轮审批、固定 CTA、网页触控尺寸、未经核实的平台文字占比规则和少文字艺术海报偏好。Stars 只记录在研究文档，不是运行时选择依据。

实际发出的 system/user 与知识包快照使用同一份序列化内容，记录 version、source revisions、规则 hash、选择的 IDs；不能只在日志中写“用了 Skill”。

## 2. 规划职责与数据契约

输入增加 `styleId: string | null` 和 `customStyle: string`，前端每次显式发送，customStyle 可以为空串。大师读取与后续编译一致的已选风格描述；null 表示未提供，不擅自覆盖前端的现有默认值。第一版不新增自动风格选择 UI，不保留旧客户端请求契约。

保留 informationQuestion、evidence、bigIdea、visualMechanism、productPresence、compositionBrief 等现有字段，新增：

```json
{
  "planningContractVersion": "commerce-design-v1",
  "sharedVisualDirection": "品牌色和字体层级一致，数字图、使用图与产品摄影各自选择合适背景",
  "modules": [{
    "taskId": "reporting-rate",
    "taskTitle": "解释回报率",
    "moduleId": "hero-freeform",
    "informationQuestion": "1000 Hz 表示什么？",
    "evidence": ["用户提供：1000 Hz"],
    "productPresence": "none",
    "designGuideIds": ["data-explanation", "visual-hierarchy"],
    "compositionBrief": "以 1000 Hz 为主信息，配报告间隔概念示意，不绘制鼠标本体",
    "bigIdea": "让读者看懂回报率这一指标",
    "visualMechanism": "大数字与等间隔刻度建立对应，不画竞品实测曲线"
  }]
}
```

此例只展示新增/相关字段，实际响应仍需现有 resultCount、reason、styleTemplateId 等字段。

响应要求 taskTitle 1–80 字，sharedVisualDirection 1–1,000 字，designGuideIds 1–2 项且去重并来自辅助指南白名单；productPresence 使用明确枚举。输入输出采用一套新契约，不增加历史读取宽松模型。

大师内部工作顺序：识别受众及资料边界；选定整套方向；逐图确定问题、证据和表达；选择模板、指南、出场方式；最后选择模块。保留明确可执行的 compositionBrief，但它是可调整建议，不能覆盖事实或用户指定构图。

不要固定给用户增加三条路线选择或每图审批。第一版在已有规划请求内形成一个连贯方向，用户仍通过现有编辑和确认流程操作。

## 3. 自由任务如何接入模块体系

增加系统提供的 `hero-freeform` 和 `suite-freeform` 执行模块，名称为“自由创意”，无强制摄影/产品展示要求。普通目录模块仍可用于明确适配的任务；无法匹配时采用自由模块，不允许模型发明任意执行 ID。

实现统一 `runtime_module_catalog(config, mode)`：深拷贝已发布目录，缺少自由模块时追加系统定义；已存在同 ID 且 mode 正确时保留现有配置，不重复追加；错误 mode 报 `RUNTIME_MODULE_CATALOG_INVALID`。该视图不写回数据库、不改发布配置 hash。

配置解析接口另附 `runtimeModules`，其内含 version、contentSha256、heroModules、suiteModules，保留原始 `config`/`contentSha256` 语义。前端将运行时目录用于生成选择与校验，配置管理的草稿仍使用真实发布/草稿数据。大师、主图批次、套图编译和单主图入口都通过同一 helper 解析模块，并在请求快照记录实际目录及 hash。当前发布目录需要补齐自由模块是新任务的执行依赖，不是旧任务兼容。

自由模块无默认绑定提示词。若工作区已有同名模块绑定，仍保留该配置；编译器必须明确把模板建议放在商品事实、平台规则、用户要求和本图目标之后，避免一个旧“完整商品居中”模板覆盖 none 任务。

## 4. 简案、用户编辑和风格的边界

自动 compositionBrief 不再追加进 moduleParameters；任务卡单独显示“构图建议”，用户修改时写入独立的“构图要求”参数。后端接收该参数后将其作为用户显式要求，与自动 taskOutline 分开传递。前后端同时移除“建议构图简案”的自动追加与特殊合并逻辑，不实现对旧值来源的推断。

用户已编辑的事实参数和构图要求在同 taskId/同 moduleId 重规划时沿用当前 preserveEdits 逻辑；任务类型变化不错误移植。删掉的参数不得自动复活。

保留用户选择的风格方向、明确配色和明确构图要求。将系统默认种子中的具体环境、机位、光线当作执行建议，图解不必假装棚拍，使用场景不必复制首图背景。sharedVisualDirection 只规定系列共性，不能发明品牌色或覆盖用户风格。

平台约束按适用范围解释：主图首张、主图附图、详情图在编译上下文分别标识为 primary/gallery/detail；后端根据 mode 和当前任务顺序计算，不能让模型自行把首张标成附图逃避约束。平台规则原文保留；只限首图的规则不泛化到所有详情图，通用真实性规则对所有任务生效。不在本次凭经验重写平台政策。

## 5. 前端与新任务状态

- 自动任务卡主标题显示必填 taskTitle，模块名称作为次级类型；手动新任务使用所选模块名作为初始标题。
- 新规划展示信息目标、表达方式、商品出场和可编辑的构图建议；技术性的仓库/hash/guide ID 留在开发快照，不进入正常用户流程。
- 请求、指纹、异步完成校验、刷新恢复同时纳入 styleId/customStyle。新请求含 `commerce-design-v1` 本地指纹版本，只恢复匹配的新契约；不匹配时提示重新规划，不转换旧记录。
- 新批次失败重试使用该批次冻结的提示词与知识版本，不调用新的大师；用户点击重新规划才重新选择指导与构图。
- 主图与套图共享任务表达和设计指导机制，继续保留各自计划、确认流程和批次身份。

## 6. 验收与上线

自动化验证真实模型请求捕获内容，覆盖知识实际注入、未知指南拒绝、无产品任务下传、自由模块全链路、风格变更导致规划过期、手动编辑保留，以及新任务刷新恢复和失败重试。不增加旧计划读取、旧字段迁移或历史重试测试。不能用“提示词包含某句话”冒充成图质量验证。

以当前鼠标为主样本，加一个非数码商品检查通用性。先做不调用图片模型的编译检查；之后使用同一输入、模型、画幅、分辨率和风格进行小批对照，记录版本、提示词、耗时、成本、文字错误、商品身份错误、信息表达和系列一致性。对于有意规划为 none 的图片，人工核验实际没有补画商品；不要求每套强制有 none。

对比图不得借用参考图未证实的参数。例如 1000 Hz 不等于系统端到端延迟 1 ms，不等于瞄准效果提升。单次对照仅判断该样本，不能宣称普遍提升。

前后端按同一契约一起更新并验证新任务；不设计新旧客户端混用或任务数据回退适配。已有数据不迁移、不删除，用户需要使用新链路时重新规划。真实图片对照单独执行，本计划阶段不调用付费生成。
