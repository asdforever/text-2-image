# 项目反推执行方案设计

## 目标

在现有爆品图反推分析之外，新增独立的“项目反推”执行层。它把已发布的反推版本转换成与参考套图一一对应的可编辑任务，并为提示词编译和来源追踪保留每张模板图的引用。图片生成仅使用当前商品图和拆解提示词，参考图仅用于分析和页面对照。

## 保持不变

- 现有参考套图、整体反推、模块拆解、绑定记录继续使用原有数据和页面。
- 主图、详情套图、白底图和画布的现有工作流不被替换。
- 项目反推是新的顶层工作区，只通过项目内的“项目反推”标签进入。

## 执行方案

每个项目反推方案绑定一个已发布的反推版本。生成方案时按版本中的 `references.ordinal` 排序，为每张参考图创建一个任务；任务通过 `referenceImageId` 和 `referenceModuleId` 与模板及模块建立一一对应关系。任务保存模板的结构字段：目标、场景/布局、信息层级、字体排版、色彩光影和适配说明，同时保存当前商品替换说明与可编辑的提示词草稿。

## 页面行为

- 无方案时直接列出所有已发布的反推版本和“生成项目方案”，无需提前绑定到主图或详情套图；未发布的草稿不进入选择列表。
- 商品输入区可选择项目中的白底图或原图，并可直接上传白底图。优先预选当前白底图，生成前确认具体商品图；没有商品图时不能出图。
- 商品名称、商品参数、核心卖点和补充要求随方案保存，补充项可留空。编译及未编译直接生成均使用保存的商品参数；修改参数后清除旧提示词，避免继续使用旧商品事实。
- 商品资料合并为常规版式的“参数填写”和“自动填写”。规划模型只依据当前商品图、用户资料和每张模板的拆解分配 `moduleParameters`；保持全部任务标识、结构、张数及顺序，返回缺项或重复任务时不覆盖现有方案。
- 每张任务展示可增删的“补充参数”，其内容进入该任务的提示词。全局资料修改后重新分配，任务参数修改后重新编译；已经生成的图片保留。
- 复用输出设置组件提供语言、模型、宽高比和分辨率。选项随方案保存，语言用于编译，模型连接与比例、分辨率用于实际出图并记录归档。
- 生成后按参考图顺序展示任务列表，每行显示模板图、模块类型、结构约束和提示词草稿。
- 任务可单独编辑和保存；保存采用修订号避免覆盖别人的编辑。
- “编译提示词”先生成每条任务的结构化提示词草稿，不触发图片生成。
- 生图阶段逐条携带商品白底图（或原图）和拆解提示词；不读取或上传参考图文件。

## 相似度边界

产品呈现须在文字拆解中逐张记录主体数量、画面位置、占画比例、留白、裁切与遮挡、接触关系，以及相机高度、前后端部件锚点、画面长轴方向和可见面。方向统一使用观看者的画面坐标，不能只写“45 度”或“朝向观者”，也不能仅由文件名推断视角；无法确定的角度与隐藏结构须说明不确定。

编译提示词明确分配依据：商品图与已确认事实决定当前商品真实结构、部件、比例、颜色、材质、纹样和标识；模块拆解决定机位、姿态与构图。需要改变视角时应重新摆放和拍摄三维商品，不能沿用输入图视角、仅二维旋转或镜像翻转；不得把参考商品的形状和部件套到当前商品上。未描述的背景、道具可合理设计，已有产品呈现约束不能自行改变。旧方案的含糊布局需要单独修正并重新编译，不能从编译步骤推断缺失的视觉信息。

系统固定任务数量、顺序和参考图对应关系，通过拆解提示词指导模块职责、机位、构图、光影和信息层级。场景与道具由模型按描述重新生成，不承诺视觉细节或像素级一致。

## 第一阶段验收

1. 参考图 N 张时，执行任务必须正好 N 条且顺序一致。
2. 每条任务的 `referenceImageId` 必须来自当前反推版本，不能跨版本引用。
3. 编辑一条任务后，其他任务内容不变，修订号递增。
4. 现有反推分析接口和页面测试继续通过。
