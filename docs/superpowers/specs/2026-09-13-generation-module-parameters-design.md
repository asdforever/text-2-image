# 主图与详情套图模块参数设计

## 背景

主图工作台和详情套图工作台已经支持选择多个生成模块，但所有模块共享同一组全局配置，无法表达“某个模块需要额外事实或创作约束”的情况。主图中的“促销信息”也不再属于当前生成流程，需要移除。

## 目标

1. 删除主图配置中的“促销信息”模块。
2. 让主图模块和详情页模块都支持按模块补充参数。
3. 参数既能使用模块推荐字段，也能由用户新增自定义字段。
4. 参数在规划和图片生成时沿模块传递，避免只保存 UI 草稿而不影响结果。
5. 不要求用户填写任何参数，空参数仍可正常生成。

## 交互设计

### 模块参数编辑器

模块选择器继续使用现有卡片选择交互。已选模块在卡片网格下方显示对应的参数编辑区，未选模块不显示参数编辑区。

每个参数编辑区包含：

- 模块名称和简短说明；
- 一组该模块的推荐字段，每行包含“参数名”和“参数值”；
- “添加参数”操作，可新增任意参数名和值；
- 每行的删除操作；
- 参数值使用短文本输入，较长的场景描述使用多行文本输入；
- 空参数不会阻止规划或生成，生成前会过滤空的参数名和值。

推荐字段只提供起点，不限制用户修改或删除。示例：

- 使用场景图：场景地点、环境元素、人物/动作、时间与光线；
- 功能对比图：对比维度、对比对象、必须展示的事实；
- 尺寸/容量/尺码图：参数列表、单位、版式；
- 包装展示图：包装内容、摆放方式、背景；
- 买家秀/博主推荐图：人物设定、使用时刻、表达重点。

如果某个模块没有专属推荐字段，则提供一个“补充说明”字段和通用新增参数入口。

### 配置变更

主图配置删除促销信息输入。历史草稿中残留的 `promotion` 字段不参与 UI，也不再传入生成参数，以保证旧数据可以读取但不会继续影响新结果。

## 数据模型

在共享生成配置中增加：

```ts
moduleParameters: Record<string, Array<{
  key: string;
  value: string;
}>>
```

键为模块 ID，数组顺序即 UI 顺序。推荐字段通过模块目录提供，首次展示某个模块时初始化；用户编辑后的字段保存在 Zustand 的生成草稿中，并随项目和模式隔离。

空对象和不存在的模块键都表示该模块没有额外参数。配置规范化需要为新草稿提供空对象，并保留历史草稿的其他字段。

## 生成数据流

主图生成每个模块时传入：

- 全局比例和图片风格；
- 当前模块 ID；
- 当前模块过滤后的参数键值。

详情套图规划为每个计划项保存同一份模块参数，并把非空参数加入画面说明上下文。按规划生成图片时，再将该模块参数传给套图 mock/后端调用。

参数传递使用结构化对象，不把键值提前拼成无法解析的大段字符串。后端尚未接入时，mock 函数保留同样的参数接口，便于后续替换真实服务。

## 约束与兼容

- 单个模块最多保存 20 行参数；参数名最多 60 个字符，参数值最多 500 个字符。
- 删除参数只影响当前模块，不影响其他模块或预置字段定义。
- 取消选择模块时保留其参数草稿，重新选择后恢复，避免误操作丢失输入。
- 旧的 `designBrief`、`creativePrompt` 等历史字段继续可被读取，但不再渲染输入框；主图 `promotion` 同样只做读取兼容，不参与生成。

## 验证范围

- 主图配置不再渲染“促销信息”。
- 选中模块后能渲染推荐参数、添加/删除参数并持久化到对应模式草稿。
- 主图和详情套图的生成调用都收到正确的模块参数。
- 套图规划项包含对应模块的非空参数。
- 现有模块选择边界、风格选择、规划排序、生成重试和历史草稿兼容测试继续通过。
