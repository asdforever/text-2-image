# 项目生成结果实时归档设计

## 目标

将项目生成结果从短生命周期任务记录升级为可恢复的项目资产与正式成品：白底图、主图、详情图和场景图生成成功后立即显示在所属项目工作区，并自动归档到该项目在正式成品库中的唯一产品条目。

## 现状与根因

- 白底图成功后已有写入项目资产的代码，但图片编辑任务仓储使用内存实现；重启后任务、尝试和版本无法恢复。
- 正式产品库同样使用内存服务，前端依赖手动创建产品和手动填写来源版本；无法代表真实项目成品。
- 项目资产已使用 PostgreSQL 与对象存储，因此项目页面可作为统一、持久的工作区资产来源。

## 架构

新增“项目成品归档”模块，作为成功输出的唯一归档 seam。调用方仅提交项目、输出类型、对象与不可变来源快照；模块负责保证每个项目只有一个正式产品条目、同一来源不会重复创建版本、并写入受控预览信息。

图片编辑仓储和正式产品库仓储各提供内存与 PostgreSQL adapter。运行时存在数据库连接时默认使用 PostgreSQL adapter；测试仍可注入内存 adapter。任务与版本的状态、来源快照和幂等键均持久化。

## 数据流

1. 白底图 Worker 调用 Provider 成功，先创建项目 `white_background` 资产，再调用项目成品归档模块创建 `white_background` 成品版本。
2. 主图与详情图批次 Worker 成功，先创建项目 `generated` 资产，再按模块模式映射为 `hero`、`detail` 或 `scene` 成品版本并归档。
3. 项目工作区重新读取 `/api/projects/{id}`，立即显示新增资产；成品库读取对应项目产品及版本，显示同一项目的全部成品。
4. 测试库不调用项目成品归档模块，仍保持独立。

## 约束

- 不复制图片对象；正式成品版本保存对已生成对象的受控引用与来源快照。
- 每个项目每个工作区最多一个自动归档产品条目；并发首次归档依靠数据库唯一约束与重读处理。
- 同一个源任务版本或生成槽位只能归档一次；重复 Worker 执行不会生成重复成品版本。
- 白底图仍必须出现在当前项目的白底图工作区；主图/详情图继续在项目生成资产与画布中可见。
- 成品库的手动“填写版本标识”入口移除，改为读取项目已成功资产/版本并按项目跳转。

## 验收

- 服务重启后，图片编辑任务、失败尝试与成功版本仍可查询。
- 白底图成功后，项目详情存在 `white_background` 资产，且项目自动成品存在同一来源的 `white_background` 版本。
- 主图、详情图批次成功后，各自存在项目资产与自动成品版本。
- 同一任务重试或接口重放不产生重复成品。
- 测试库结果不进入正式成品库。
