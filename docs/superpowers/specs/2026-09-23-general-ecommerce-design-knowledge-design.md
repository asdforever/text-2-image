# 通用电商视觉规划知识库设计

## 目标

让主图和详情图规划从“列出商品信息并写一段生图提示词”升级为“按购买决策组织内容、按视觉系统组织版式、按相邻模块控制节奏”。知识必须适用于多个商品品类，鼠标等具体品类只能作为额外覆盖层。

## 设计判断

当前规划大师只描述模块选择、信息分配和构图简案；模块规划器的通用提示词又默认先写完整商品主体与 Logo。结果是每张图都能保持商品身份，却缺少跨图层级、版式变化和商品出场控制。

## 方案

### 1. 通用设计知识包

增加一个版本化的设计知识包，内容分为：

- 视觉原则：焦点、层级、对齐、对比、邻近、比例、留白和网格。
- 页面叙事：识别、差异、场景、尺度、细节、规格、信任和收束。
- 版式家族：中心聚焦、左右分栏、网格卡片、场景叙事、局部标注、拆解、规格表和数据证明。
- 商品出场规则：完整、局部、场景、结构、仅证据和不出现。
- 移动端规则：安全裁切、可读字号、对比度、放大和缩略图。
- 失败规则：重复主视觉、连续同角度、信息堆叠、无依据承诺、低对比文字和关键证据不可见。

### 2. 案例标注层

参考图片不直接作为长文本提示词注入。每个案例保存为带标签的知识卡片，至少包含 `pageType`、`moduleRole`、`narrativeStage`、`productPresence`、`subjectScale`、`camera`、`layoutFamily`、`textDensity`、`evidenceType`、`previousModuleContrast` 和 `avoid`。

案例按品类和品牌提供可选覆盖，但不改变通用字段。检索时优先使用“页面类型 + 模块职责 + 视觉目标”，再用品类和品牌做风格过滤。

### 3. 规划大师输出扩展

规划大师在套图级别输出 `narrativeStages`、`visualRhythm`、`productPresencePlan` 和 `layoutFamilies`；每个任务输出 `informationQuestion`、`productPresence`、`subjectScale`、`layoutFamily`、`evidence`、`previousModuleContrast` 和 `avoid`。

规划大师只决定整套图的阅读顺序和视觉分工，不写最终生图提示词。

### 4. 模块规划器输入与提示词

模块规划器接收通用设计约束和任务级版式字段。通用提示词不再默认每张图必须以完整商品和 Logo 开场；只有 `productPresence=full` 或模块职责需要时才要求完整商品。`detail`、`partial`、`context` 和 `none` 必须覆盖完整商品重复出现的场景。

模块规划器继续负责单张图的主体、镜头、网格位置、文字区域、光线和最终画面描述，但不能覆盖规划大师的 `productPresence`、`layoutFamily`、`informationQuestion` 和 `avoid`。

### 5. 设计审稿器

生成前检查规划冲突，生成后检查结果。硬性失败包括：商品身份变形、关键证据不可见、连续重复完整商品、连续重复视角、文字在移动端不可读、平台约束不满足和无来源承诺。通过阈值为 20 分制至少 16 分，且识别、层级、证据、可读性四项不能低于 2 分。

## 数据流

```text
设计知识包 + 案例检索
        ↓
规划大师：套图叙事与任务版式
        ↓
模块规划器：单张图执行提示词
        ↓
设计审稿器：规则检查与评分
        ↓
确认快照：保存规则版本、案例引用和审稿结果
```

## 兼容与范围

- 不修改历史规划快照的含义；新字段缺失时按旧规划读取。
- 先实现静态通用知识包和规则检查，不引入向量数据库或在线案例抓取。
- 首轮验证覆盖主图和详情套图各一条流程，并用至少三个品类的固定测试样本避免鼠标专用化。
- 规则与案例都必须带版本号和哈希，便于追溯生成结果。

## 验收标准

- 同一套图不再连续使用相同的完整商品主视觉、角度和版式。
- 每张图都能回答一个明确的购买问题。
- 规划结果能明确说明商品是否出现、出现比例、视觉焦点和相邻图差异。
- 模块规划器不能绕过任务级版式约束重新加入完整商品。
- 设计审稿器能稳定拦截重复、低对比、无依据承诺和移动端不可读问题。
- 通用规则在至少三个不同品类上可复用。
