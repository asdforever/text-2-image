# 通用视觉 Skill 接入 V2

当前实现复用 freestylefly/awesome-gpt-image-2 的 22 个通用模板；来源版本和许可见 `backend/app/data/gpt_image_2_style_library/NOTICE.md`。

## 执行流程

1. 规划大师读取完整模板索引，按每张图的职责、风格和场景选择模板。商品事实及平台规则优先。
2. 每个任务保存 `styleTemplateId`、`visualStyleTags`、`sceneTags`、`referenceCaseIds`、`bigIdea` 和 `visualMechanism`。选型自动完成，沿用已有规划确认流程。
   新调用返回的模板 ID、主视觉想法和具体表达方式必须非空；缺失、空白、未知模板或错误案例归属均拒绝保存为成功。历史规划仍可读取。
3. 单张提示词编译器读取该模板的指导、避坑和对应分类模板原文，把画面想法落实为商品、环境、图文的关系。模板中的品牌、参数和文案仅为示例，不得挪用。
4. 模板内容摘要、上游提交和选择的 ID 进入编译快照。规划大师还保存实际读取的索引与系统提示词。
5. 没有大师任务书的直接编译、以及旧规划，读取完整模板摘要，由单张规划模型选择表达方式。这条路径不增加额外模型调用，也不会加载所有分类的长模板正文。

模板可以跨品类使用，不预设圆盘、控制台、波形或任何固定画面。白底图、规格图不需要强行加入视觉隐喻。概念表现不等于实测证据，未知内部结构和性能数据仍不可生成。

模板与风格种子的材质描述只影响环境和版式，不能改变商品本体。商品可见标识不能因品牌名未知而被删除；已知部件总数不能作为猜测隐藏部件位置或功能的依据。单张提示词必须包含逐字上图文案，因为图片模型不会读取仅供界面展示的 `exactCopy` 字段。

## 接入范围

主图批量编译、详情页编译及单张主图共享 V2 编译入口。现有最终 imagePrompt 格式和旧快照校验方式保持兼容。前端通过 modulePlanId 引用后端保存的任务书，不需要把全部模板数据传回服务器。

安装到 Codex 的 Skill 与应用内知识包是两套独立加载路径：前者服务开发代理，后者随应用代码发布。模板原文件保持原样，应用只适配选型流程和 JSON 输出契约。

## 验证范围

自动测试覆盖：模板选择及原文加载、未知 ID/案例归属拒绝、调用间数据隔离、规划到单张编译的选型传递、快照版本记录、旧规划与原有 V2 编译兼容。真实模型验证用于观察选型和提示词行为；这些结果不等于已证明图片审美提升。

当前不实施独立文字合成器，也不将案例图自动作为生图参考。是否改善成图，需要后续以真实商品与相同模型生成对照样图。

### 页面“规划结果无效”的后续修复

- 排查实际失败记录发现，运行中的旧 Python 服务读取了更新后的 Skill 文件，却未加载支持新字段的校验代码。日志将 `styleTemplateId`、`bigIdea` 等全部判为 `extra_forbidden`，对应快照也没有 `styleLibrary`。已重启本机 API 加载新代码；后续修改 Python 代码须确认服务实际重载，不能只依赖文件已保存。
- 新服务实测还遇到模型自行增加 `summaryNote`。现在结构或模块选择校验失败时，自动反馈错误路径和原始输出，要求模型完整纠正一次；第二次仍不合法才失败。仍严格校验字段、模板、案例、模块与数量，不静默删除字段或编造默认值。鉴权、配额、网络等服务错误不触发此格式纠正。
- 每次实际请求及校验问题保存在 `snapshot.modelAttempts`；纠正沿用同一个规划记录、幂等键与原有总超时上限。相关测试更新为 99 项通过，覆盖纠正成功、次数限制、故障不误重试与重放不重复调用。
