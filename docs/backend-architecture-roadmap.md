# 后端架构实施路线图

本文档是后端模块化实施的阶段总表，记录每个阶段的目标、依赖、可验收能力和当前状态。后续实施、验收和复盘都以本文档为准，避免只依赖对话记录。

## 总体原则

- 第一版按单用户、单工作区实现。
- 保留 `actor_id`、`workspace_id` 身份上下文接口，未来接入登录和多租户时替换适配器。
- 生成只读取已发布配置，不读取未保存草稿。
- 每次生成都保存不可变快照：市场、平台、模型、风格、模块参数、生成张数、提示词版本和输入素材版本。
- 每个阶段完成后，必须通过该阶段的验收条件，才能开始依赖它的阶段。
- 本文档中的“已完成”只在代码、测试和验收证据齐全后填写。

## 阶段 0：运行时基线

对应 OpenSpec：`backend-runtime-baseline`

### 实现能力

- 服务端拥有的单用户身份和工作区上下文。
- 路由、应用服务、领域规则、仓储和适配器分层。
- 统一成功响应、错误信封、请求 ID 和稳定错误码。
- 创建、上传、发布和异步触发操作的持久化幂等。
- Alembic 唯一迁移入口、漂移检测、并发锁、升级和回滚检查。
- FastAPI 与 Node 并行运行、选择性代理和无损回滚。

### 验收门槛

- suite/input-image 接口契约测试通过。
- 重试不会重复创建数据库记录或对象。
- `/api/health` 和 `/api/ready` 语义分离且故障响应正确。
- 迁移升级/回滚和 Node 切回冒烟测试通过。

## 阶段 1：项目与素材域

### 实现能力

- 持久化项目/工作区及项目状态。
- 源图、白底图、生成图片的资源版本和对象 key 管理。
- 上传、预览、选择、删除和孤儿对象清理。
- 项目素材与全局资源库之间的引用关系。

### 验收门槛

- 服务重启后项目和素材仍可读取。
- 上传失败时数据库和对象存储都不留下孤儿数据。
- 删除项目或素材不会误删其他项目资源。

## 阶段 2：生成配置中心

### 实现能力

- 国内/国外两级市场，以及组内具体电商平台。
- 生图模型、模型约束和支持的分辨率。
- 风格大类和风格项，每个大类最多 4 项。
- 主图模块和详情页模块的内置目录及提示词版本绑定。
- 草稿、已发布版本和放弃编辑。

### 验收门槛

- 未发布草稿不影响工作台和生成请求。
- 发布后新生成只读取最新已发布版本。
- 删除配置项不破坏历史快照。
- 无效平台、模型、风格或提示词绑定会阻止发布。

## 阶段 3A：最小真实生图切片

### 实现能力

- 接入多模态提示词编译模型，以单张项目源图、模块说明和补充参数生成实时任务提示词、可见事实与无法确认项。
- 将商品真实性、具体电商平台和全局风格作为服务端只读约束卡，按固定顺序与用户确认的实时任务提示词组合。
- 选择一个有效项目素材、一个主图模块和一套已发布配置，先编译并确认提示词，再调用第一个真实图片 Provider。
- 使用 `/v1/images/edits` multipart 上传源图，阶段 3A 固定一次生成一张图片。
- 将请求参数、提示词版本、配置版本、输入素材版本、最终提示词与非敏感 Provider 参数写入不可变任务快照。
- 结果图片写入对象存储、创建 `generated` 项目资产并在主图工作台显示；失败不覆盖历史结果。

### 验收门槛

- 可以从前端发起一次真实请求并看到真实图片。
- Provider 失败时任务进入失败状态，错误可读且不泄露密钥。
- 修改配置后，历史结果仍显示生成时的原始快照。

## 阶段 3B：生成任务编排

### 实现能力

- 一个模块生成 1-4 张图片，批次编译后逐模块审阅一条实时任务提示词。
- 批量任务、槽位、尝试记录和结果版本已通过 `generation_batches` 等四张表持久化。
- 单槽位重试、部分失败、取消、幂等提交、租约恢复和调用结果不确定时的人工重试已实现。
- `generation-worker` 以数据库队列执行已确认槽位；可使用 `--once` 进行单次部署冒烟。

### 验收门槛

- 部分失败只重试失败槽位。
- Worker 重启后未完成任务可以继续执行。
- 同一个幂等键不会产生重复 Provider 请求。

## 阶段 4：规划与套图生成

### 实现能力

- 详情页规划和结构计划。
- 计划确认、分类提示词和 RAG 引用快照。
- 详情页模块按顺序生成图片。
- 主图与套图共享市场、模型、风格和提示词解析能力。

### 验收门槛

- 规划确认后才能生成详情页图片。
- 单个模块规划可编辑，不影响其他模块。
- 计划和生成可以基于快照重放。

## 阶段 5：工作台协作状态

### 实现能力

- 任务提示词和生成参数编辑。
- 当前版本/最终版本选择。
- 画布布局、视口和节点状态持久化。
- 计划、任务、图片和资源库之间的引用与归档。

### 验收门槛

- 刷新页面或重新打开项目后可以继续工作。
- 并发编辑不会静默覆盖较新的版本。
- 历史引用保持可追溯。

## 阶段 6：图片编辑与项目成品档案

### 实现能力

- 服务端持久化图片编辑会话、操作草稿和乐观修订号，刷新后可恢复编辑状态。
- OCR 结果按源图片版本和幂等键保存，保留文字区域、模型信息和识别时间。
- 编辑提交固化源图、操作、提示词和生成配置快照，通过异步任务记录生成尝试、失败原因和成功版本。
- 失败尝试可重试，已完成任务可再次生成；历史尝试和历史版本保持不可变。
- 成功版本可以分别设为当前版本和终版，并通过修订边界防止并发覆盖。
- 项目创建时自动建立唯一成品档案；源图、白底图、主图、详情图、场景图和编辑结果实时关联，媒体信息仍以项目资产为事实来源。
- 生成或发布版本保存完整不可变来源快照；手动上传资产允许没有生成版本。
- 正式产品版本提供受控预览，归档和清理遵守项目素材、编辑版本和产品版本的引用关系。
- 提示词测试成功后自动进入统一“测试结果”库，并保存提示词名称、版本、输入、参数、模型与耗时；失败测试不入库，任务重放不重复创建。
- 项目资产与提示词测试产物保持隔离：项目资产自动进入所属项目档案，但测试产物只有明确导入项目后才进入正式档案。

### 验收门槛

- 编辑会话刷新后可恢复，失败尝试可重试，成功版本可选择当前版本和终版。
- 编辑失败不会覆盖原始图片，重复请求不会改写历史尝试或产生重复发布版本。
- 创建项目后立即能在成品库看到空档案，新增和删除项目资产会实时同步。
- 提示词测试成功后可从页面打开测试库并按提示词名称或版本识别，失败测试不会产生不完整记录。
- 项目成品档案可查看资产和版本状态及受控预览，跨工作区请求不泄露对象地址。
- 删除和归档遵循对象存储引用计数与待清理重试规则。
- 后端全量测试、前端类型检查、组件测试、端到端流程和生产构建全部通过。

## 阶段 7：生产化能力

### 实现能力

- 登录、身份认证、角色权限和多工作区。
- 审计事件、结构化日志、指标、链路追踪和任务关联 ID。
- 限流、配额、Provider 成本统计和数据保留策略。
- 备份、灾备、部署、迁移和回滚演练。

### 验收门槛

- 不同用户和工作区之间完全隔离。
- 关键操作可审计和追踪。
- Provider 失败、队列堆积和存储故障可监控并告警。

## 更新规则

- 开始阶段：将状态改为“实施中”，记录对应 OpenSpec change。
- 完成代码和测试：将状态改为“待验收”，补充命令和结果。
- 用户验收通过：将状态改为“已完成”，再开始后续依赖阶段。
- 需求变更时，先更新本文档和对应 OpenSpec，再修改代码。
