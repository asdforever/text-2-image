## Context

白底图工作区当前通过 `BaseImageWorkspace` 接收本地文件，并调用 Zustand store 的 `addProjectAssets` 将其转换为项目内 `source` 资产。全局素材库是另一套数据库驱动的数据源，通过 `listAssetLibraries` 和 `listAssets` 返回图片素材及 MinIO 预签名 URL；两套数据目前没有转换边界。数据库暂时不可用，因此实现必须能够通过前端 mock 验证，同时为恢复后的真实接口联调保留清晰入口。

## Goals / Non-Goals

**Goals:**

- 在不改变本地提交行为的前提下，为白底图工作区增加图片素材库输入。
- 将素材库图片转换成与本地上传图片一致的项目原图，使后续选择、生成和导出流程无需区分来源。
- 使用稳定的素材标识完成来源追踪和项目内去重。
- 隔离素材库故障，使数据库不可用时本地提交仍可工作。

**Non-Goals:**

- 不把生成后的白底图或套图写回素材库。
- 不在本次变更中调整素材库后端、数据库迁移或 MinIO 存储策略。
- 不在本次变更中把整个项目工作区从 Zustand/localStorage 迁移到后端持久化。

## Decisions

### 1. 使用独立的素材库选择对话框

在白底图工具栏保留“提交素材”，并新增“从素材库选择”。新入口打开独立选择对话框：先从图片素材库中选择库，再在该库的图片网格中多选素材，最后统一确认。

这样可以保持两个入口的心智模型清晰，也避免把远程加载状态混入浏览器文件选择流程。替代方案是把素材库嵌入右侧项目资产面板，但该面板目前只描述项目内资产，混入全局素材会模糊“可用素材”和“已加入项目素材”的边界。

### 2. 素材库读取复用现有 API 客户端

选择器复用 `listAssetLibraries` 和 `listAssets`，在客户端过滤 `assetType="image"`。加载库列表和加载库内素材分别维护 loading、error 和 empty 状态，并提供重试动作。

不新增后端聚合端点，因为现有接口已足以支撑流程，且当前数据库不可用于验证。前端测试通过 mock 这两个 API 函数覆盖成功、空数据和失败分支。

### 3. 通过专用 store 动作导入素材库图片

为项目 store 增加专用的批量导入动作，而不是将远程素材伪装成浏览器文件后复用本地文件校验。素材库图片已经由服务端接收并具备自身元数据，本地文件大小和 MIME 校验不应再次决定它能否加入项目。

项目 `Asset` 增加可选来源信息，至少包含来源类型、素材库 ID 和素材 ID。导入后的资产仍使用 `type="source"`，因此现有白底图生成流程只消费统一的项目原图结构。

### 4. 使用稳定 ID 去重，URL 仅作为预览快照

同一项目内以 `(libraryId, assetId)` 作为素材库来源唯一键。确认添加时由 store 原子地过滤已存在项，并返回新增与跳过数量供 UI 反馈；不使用名称或 URL 去重。

素材 API 当前返回的 MinIO URL 可能是预签名 URL，因此它只作为当前预览快照保存，不能充当来源身份。数据库恢复后的集成验证需要确认 URL 有效期对 localStorage 恢复的影响；若刷新后 URL 会失效，应在后续后端持久化工作中根据素材 ID 重新解析 URL。

### 5. 失败边界限制在选择器内

素材库请求只在用户打开选择器后触发。请求失败时，错误和重试动作留在对话框内，不修改项目现有资产，也不禁用本地提交按钮。确认导入必须基于已成功加载且带可用图片 URL 的素材。

## Risks / Trade-offs

- [预签名 URL 在 localStorage 中过期] -> 使用素材 ID 作为身份；本次记录风险，数据库恢复后验证并决定是否增加按 ID 刷新 URL 的接口。
- [素材在选择后、确认前被服务端删除] -> 导入只保存当前可用快照；真实联调时验证服务端 404/失效 URL 的展示行为。
- [旧的持久化项目没有来源字段] -> 来源字段保持可选，本地上传及历史数据按上传来源处理，不要求迁移现有 localStorage。
- [数据库不可用导致端到端流程暂时无法验证] -> 先以 mock 覆盖前端契约、去重和错误分支，将真实接口和 MinIO 验证保留为独立任务。

## Migration Plan

1. 以可选字段扩展项目资产结构并增加素材库批量导入动作，确保旧 localStorage 数据仍可读取。
2. 增加素材库选择器和白底图工作区入口，使用 mock API 完成交互测试、类型检查和构建验证。
3. 数据库恢复后连接真实素材库数据，验证图片筛选、预览 URL、批量导入和刷新后的可用性。
4. 若真实联调失败，可隐藏新入口或回退选择器组件；原有本地提交路径不受影响。
