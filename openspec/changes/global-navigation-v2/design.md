## Context

当前入口由 `src/routes/router.tsx` 提供欢迎页和项目工作台两条 TanStack Router 路由；工作台内部已有工具栏和白底图、套图、视频 tab。项目管理能力主要存在于欢迎页，提示词资源页面 `StyleLibraryPage` 属于另一套旧的手动路由，任务状态则分散在项目和生成组件中。实现需要在不破坏现有项目 store、API client 和主题 token 的前提下收拢入口。

## Goals / Non-Goals

**Goals:**

- 让四个业务分支共享一套可复用的全局侧栏和页面壳层。
- 将现有页面能力迁移或包装到统一路由，保证 URL、浏览器历史和激活态一致。
- 删除创建流程中的素材步骤，保留项目工作台内的素材提交。
- 让项目管理、提示词商城和任务中心复用现有数据边界，避免复制项目或资源状态。
- 在亮暗主题和窄窗口下维持可读、可操作的导航布局。

**Non-Goals:**

- 本 change 不引入新的后端服务、权限体系或多用户协作。
- 提示词商城不实现支付、计费、第三方上架审核或社区评论。
- 任务中心不改变现有生成任务执行协议，只聚合展示和触发已有查询/重试能力。

## Decisions

### 1. 使用统一应用壳层承载主导航

新增带侧栏的根布局组件，由根路由渲染侧栏和内容 Outlet；四个分支使用稳定路径，例如 `/workspace`、`/projects`、`/prompts`、`/tasks`。项目工作台继续使用 `/projects/:projectId`，从项目管理和任务中心跳转时携带项目或任务上下文。

选择根布局而不是每页复制侧栏，是为了确保激活态、主题按钮、窄窗口折叠和键盘导航行为一致。替代方案是在每个页面独立添加导航，短期改动少但容易出现样式和返回行为分叉。

### 2. 工作台作为项目上下文分支

“工作台”入口在没有当前项目时进入项目选择/最近项目视图；选定项目后进入现有工作台路由。工作台内部的白底图、套图、视频 tab 保持不变，侧栏只负责跨业务分支，不替代内部工具栏。

这样可以区分全局业务导航和项目内操作，避免把项目切换、资产管理和生成工具混在同一层。替代方案是让工作台入口固定指向最近项目，但首次使用和项目被删除时会出现悬空路径。

### 3. 项目管理复用 project store

项目管理页面直接读取 `useProjectStore` 的项目列表和创建 action，并在页面层增加排序、搜索、进入工作台和归档/删除确认。项目素材仍由项目 store 管理，不在全局管理页复制资产对象。

选择复用现有 store 可以保持项目创建、素材归属和持久化一致；替代方案是新增管理 API 状态层，会造成本地 mock 数据的双写和刷新不一致。

### 4. 提示词商城包装现有资源页面

将 `StyleLibraryPage` 的资源查询、模板详情、复制草稿能力抽取为提示词商城页面；图片资源继续保留在资源库能力中，但商城默认聚焦 `prompt_template`。应用模板时通过当前项目/生成阶段上下文传递模板版本 ID，不直接修改已运行任务的提示词快照。

该方案复用现有 API client 和版本模型，能保留历史快照稳定性。替代方案是创建全新的商城数据模型，无法复用已存在的模板版本和发布状态。

### 5. 任务中心采用聚合查询与来源定位

任务中心按项目聚合现有任务数据，提供状态筛选、进度展示、失败重试和“进入项目”操作。重试调用既有任务 action，成功或失败反馈只更新任务中心的查询结果，不在任务中心维护另一份任务实体。

### 6. 创建流程改为两步或单页表单

删除 `ProjectCreateDialog` 的素材上传 step 和相关文件状态，只保留产物选择与项目资料校验；创建后传递空素材列表，用户在工作台继续提交素材。采用两步结构（产物选择 -> 项目资料）以保留现有流程认知，同时减少无效步骤。

## Risks / Trade-offs

- [旧手动路由与新 TanStack 路由并存] -> 先明确主入口只使用统一根路由，旧页面通过包装组件迁移，避免新增第三套路由。
- [工作台入口没有当前项目] -> 提供最近项目选择和空项目提示，不把任意项目 ID 写死在导航中。
- [任务聚合查询成本高] -> 首版限制查询范围和分页，优先展示最近更新任务；后续再增加服务端聚合接口。
- [商城应用模板误改历史任务] -> 应用只创建新的草稿或生成请求，禁止覆盖已完成任务的提示词快照。
- [窄窗口侧栏挤压内容] -> 复用现有最小宽度策略，并提供侧栏折叠入口；在 1120px、1440px 和 1920px 做布局回归。

## Migration Plan

1. 抽取全局应用壳层和主导航，先接入现有欢迎页与工作台路由。
2. 将欢迎页最近项目整理为项目管理页，并保留旧 URL 的兼容跳转。
3. 删除创建对话框素材 step，补充无素材创建回归测试。
4. 将风格库页面重命名/包装为提示词商城，接入模板搜索、详情和复制入口。
5. 新增任务中心聚合视图，接入任务状态和失败重试。
6. 完成主题、响应式、路由历史和全量测试后，再移除旧页面入口。

回滚时可保留统一壳层和路由重定向，只恢复创建对话框的旧页面结构；项目数据和提示词版本不会因导航回滚而丢失。

## Open Questions
