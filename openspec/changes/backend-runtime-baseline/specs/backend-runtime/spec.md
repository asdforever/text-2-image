## Purpose

为单用户本地部署提供可验证、可替换的后端运行时边界，使项目、配置和生成业务能够共享一致的身份上下文、响应契约、错误处理和幂等语义，并为未来认证与多工作区扩展保留接口。

## ADDED Requirements

### Requirement: 服务端拥有的单用户上下文

系统 SHALL 为每个业务请求解析一个由服务端拥有的身份上下文，至少包含 `actorId`、`workspaceId` 和角色信息。当前单用户模式 SHALL 使用配置提供的本地上下文；客户端不得通过请求体、查询参数或普通请求头覆盖该上下文。

#### Scenario: 请求获得本地上下文
- **WHEN** 单用户模式下请求项目或配置资源
- **THEN** 系统使用本地上下文执行资源的创建、读取、更新和删除，并在持久化记录中保留对应的工作区归属

#### Scenario: 客户端尝试伪造工作区
- **WHEN** 客户端提交与服务端本地上下文不一致的工作区标识
- **THEN** 系统忽略该标识或拒绝请求，并且不得访问另一个工作区的数据

### Requirement: 稳定的 API 响应与错误契约

业务 API 的成功响应 SHALL 使用统一的 `data` 信封并包含 `requestId`。失败响应 SHALL 使用 `error.code`、`error.message` 和 `requestId`，不得返回 SQL、堆栈、密钥或对象存储内部路径。

#### Scenario: 请求成功
- **WHEN** 请求通过校验并完成业务操作
- **THEN** 响应包含可解析的 `data` 字段和与请求关联的 `requestId`

#### Scenario: 校验或依赖失败
- **WHEN** 请求参数无效或数据库/对象存储不可用
- **THEN** 系统返回稳定错误码和可理解消息，并隐藏内部异常细节

### Requirement: 请求 ID 传递

系统 SHALL 接受合法的请求 ID；请求未提供合法 ID 时 SHALL 生成新的唯一 ID。该 ID SHALL 同时出现在响应和服务日志上下文中。

#### Scenario: 调用方提供请求 ID
- **WHEN** 请求携带合法的 `X-Request-ID`
- **THEN** 响应返回相同的请求 ID，日志能够使用该 ID 关联请求

#### Scenario: 调用方未提供请求 ID
- **WHEN** 请求未携带请求 ID 或携带非法值
- **THEN** 系统生成新的请求 ID，并将其写入响应

### Requirement: 有副作用操作的持久化幂等

需要创建、上传、发布、删除或触发异步工作的 API SHALL 支持幂等键。相同作用域、相同幂等键和等价请求重复提交时 SHALL 返回第一次操作的等价结果，不得重复创建记录、对象或任务；同一幂等键用于不同请求时 SHALL 被拒绝。

#### Scenario: 使用相同幂等键重试
- **WHEN** 客户端因网络超时使用相同幂等键重新提交等价写请求
- **THEN** 系统返回第一次请求的结果，并且数据库和对象存储只产生一份副作用

#### Scenario: 使用幂等键提交不同请求
- **WHEN** 客户端使用已完成请求的幂等键提交不同载荷或不同资源作用域
- **THEN** 系统返回幂等键冲突错误，不执行第二次操作

#### Scenario: 进程重启后重试
- **WHEN** 服务重启后再次收到已完成请求的相同幂等键
- **THEN** 系统仍能识别历史结果，不因进程内缓存丢失而重复执行

### Requirement: 依赖就绪语义

系统 SHALL 区分进程存活和依赖就绪。存活检查不得要求数据库或对象存储可用；就绪检查 SHALL 检测本阶段声明的外部依赖，任一依赖不可用时返回 503 和稳定错误信封。

#### Scenario: 进程存活但依赖不可用
- **WHEN** FastAPI 进程能够处理请求但数据库或对象存储不可连接
- **THEN** 存活接口返回成功，就绪接口返回 503 并指出不可用依赖
