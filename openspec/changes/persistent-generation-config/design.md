## Context

现有生成配置由 `src/lib/generation-config.ts` 定义完整领域结构，并由 `useGenerationConfigStore` 以 localStorage 保存草稿与发布版本。工作台已消费该发布配置和不可变快照，但 FastAPI 只有项目、素材和提示词域，没有生成配置持久化模型。提示词服务已经能读取模板和具体版本，项目域已经提供单用户工作区、统一错误、持久化幂等和迁移边界。

## Goals / Non-Goals

**Goals:**

- 将既有的生成目录、绑定和版本语义移入服务端，并保留稳定的前端模型。
- 让生成配置页可跨刷新和服务重启读取草稿、已发布版本及历史版本。
- 为阶段 3A 提供只依赖已发布配置的解析结果和可嵌入任务快照的版本内容。

**Non-Goals:**

- 不创建生成任务、队列、Worker 或图片 Provider 调用。
- 不允许配置接口修改主图或详情页的内置模块目录。
- 不迁移或重写本次变更前浏览器 localStorage 中的草稿；首次服务端读取使用当前默认目录，用户可在配置页重新保存。
- 不修改既有项目资产和提示词商城的业务所有权。

## Decisions

### 1. 使用版本化 JSON 文档，而非为每个目录项建立可变关系表

新增 `generation_config` schema，其中 `config_versions` 保存每个工作区的不可变发布文档、递增版本号、内容哈希和时间戳；`config_drafts` 保存当前工作区唯一的可变草稿文档及其基线发布版本。文档使用与现有 `GenerationConfig` 对齐的 JSON 形状。

市场、模型、风格和绑定需要作为一个原子配置一起发布，生成任务也必须保存完整快照；以版本化文档处理可以直接保留历史配置，不会在删除目录项时产生级联删除或复杂的历史重组。替代方案是多个规范化目录表加版本关联表，查询和发布事务更复杂，且阶段 2 没有跨配置项独立审计需求，暂不采用。

### 2. 服务端拥有默认目录与发布验证

首次读取某工作区时，服务使用和现有前端一致的默认市场、模型、风格和内置模块创建版本 1。验证器在写草稿和发布前规范化 ID、检查唯一性、市场范围、模型分辨率、每类四个风格上限、内置模块不变性和绑定槽位。

默认目录不能从浏览器提交，防止不同客户端得到不同初始配置。前端常量将逐步降级为显示兼容和类型辅助，后端默认值是发布配置的权威来源。

### 3. 提示词绑定保留具体版本快照引用

配置文档中的每个绑定保存模板 ID、版本 ID、槽位和目标 ID。发布服务通过提示词仓储验证版本存在且属于模板，再填充名称、版本号和内容哈希等展示元数据。配置历史保留这些字段，不在读取历史配置时追随提示词商城的当前默认版本。

替代方案是在发布时仅存模板 ID 并在生成时解析默认版本；这会让配置发布后的提示词商城修改改变未来结果，违背可追溯性，不采用。

### 4. API 以文档草稿和显式发布为边界

新增以下资源：

- `GET /api/generation-config`：当前已发布版本。
- `GET`、`PUT /api/generation-config/draft`：读取或替换当前草稿；首次读取以当前发布版本初始化草稿。
- `POST /api/generation-config/publish`：验证草稿并创建新版本。
- `DELETE /api/generation-config/draft`：放弃草稿并恢复到当前发布版本。
- `GET /api/generation-config/versions/{version}`：读取历史发布版本。
- `GET /api/generation-config/resolve`：返回当前已发布版本及其面向阶段 3A 的解析视图。

使用整份草稿替换契合当前配置页的本地编辑模型，避免在第一版为每个卡片建立独立写接口。写入沿用现有持久化幂等端口；路由只做请求解析和响应映射。

### 5. 前端先切换配置中心，再切换工作台选择器

新增 API 客户端和远程配置适配层。配置页加载服务端草稿，编辑继续复用现有纯函数校验和表单组件，保存草稿与发布调用 API；放弃操作从服务端重载。主图和套图选择器在配置页迁移稳定后读取当前已发布配置，不再读取 localStorage 已发布副本。

分两步可以让配置页先成为唯一事实来源，并把选择器迁移控制在同一数据形状内。阶段 3A 之前不把此解析结果连接到真实 Provider。

## Risks / Trade-offs

- [风险] JSON 文档缺少数据库级逐项约束 → 缓解：服务端验证器、内容哈希、草稿/发布契约测试和不可变已发布记录。
- [风险] 首次服务端默认目录与旧前端默认值漂移 → 缓解：从同一受控默认目录生成测试夹具，并用契约测试比较关键市场、模型、风格和模块 ID。
- [风险] 提示词版本在发布后被删除 → 缓解：发布时验证，历史配置中保留版本元数据；后续生成对历史快照不依赖当前模板读取。
- [风险] 多标签编辑覆盖草稿 → 缓解：草稿包含基线发布版本和更新时间；本阶段返回稳定冲突，阶段 5 再加入更细粒度并发编辑体验。
- [风险] 前端与后端切换期间出现两套配置 → 缓解：配置页完成 API 接入后，工作台只读取服务端发布版本；localStorage 仅作为不再写入的兼容回退，随后移除。

## Migration Plan

1. 新增 schema、版本表和草稿表的 Alembic revision，不触碰项目素材与提示词表。
2. 部署后首次配置读取按当前默认目录创建已发布版本 1 和对应草稿，不在应用启动时执行 DDL 或预写全部工作区。
3. 前端先发布 API 客户端与配置页，再将主图、套图选择器切到已发布读取；旧 localStorage 不再作为新生成的来源。
4. 回滚优先撤回前端和路由流量，保留已发布配置和草稿记录；不对包含真实使用历史的版本执行 Alembic downgrade。
