## Context

现有生成工作台把市场、模型和风格目录定义在 `src/lib/generation-workspace.ts`，主图和套图草稿由项目级 Zustand store 持久化。市场和模型选择器直接写死选项，风格库由静态数组提供，生成请求目前只携带项目草稿参数。新能力是全局配置，不能跟单个项目草稿混在一起；同时历史生成必须继续使用生成时的值。

## Goals / Non-Goals

**Goals:**

- 提供一个全局、可保存的配置中心，覆盖市场、模型、图片风格和提示词绑定。
- 将电商市场按国内/国外分组，并在每组下维护具体平台。
- 让主图/详情页模块保持内置，同时允许按模块绑定提示词。
- 允许每个已选主图/详情页模块独立设置生成张数，并将张数写入生成快照。
- 将已保存配置解析成生成时的不可变快照。
- 在现有前端 mock/API 结构下保持可测试，并为后续服务端持久化留下稳定边界。

**Non-Goals:**

- 本次不开放主图模块或详情页模块本身的增删改。
- 本次不改写历史任务、历史图片或已经记录的提示词内容。
- 本次不实现真实生图供应商能力或模型推理逻辑。

## Decisions

### 1. 使用独立的全局配置状态

新增独立的生成配置状态层，保存 `draft`、`published` 和递增版本号；项目 store 继续只保存项目草稿、运行状态和历史数据。这样可以避免一个项目的临时选择覆盖全局配置，也能让保存边界清晰。

备选方案是把配置直接挂在 `useProjectStore` 上，但这会把全局目录和项目生命周期耦合在一起，并增加重置/迁移风险。

### 1.1 市场采用扁平条目加固定分组

市场目录继续使用稳定 ID 的扁平条目，每条增加 `marketScope`（`domestic` 或 `overseas`）表示所属大类。配置中心和工作台按分组渲染具体平台，绑定和草稿仍引用具体市场 ID；旧的 `domestic`/`international` 聚合值迁移到对应默认平台。

### 2. 目录采用稳定 ID，删除采用“从当前目录移除 + 快照保留”

市场、模型、风格大类、风格项和提示词绑定都使用稳定 ID；保存配置时保留版本化的完整目录快照。删除只影响后续可选项，历史生成引用快照中的名称、描述和能力信息，不依赖当前目录反查。

这样既满足用户的删除需求，也避免硬删除导致历史任务无法展示。当前草稿若仍引用已删除 ID，生成前由校验层报错并要求重新选择。

### 3. 提示词绑定引用具体版本

绑定记录槽位类型、目标条目 ID 和 `promptVersionId`，保存前通过已有提示词解析能力确认版本存在且可用。生成快照同时写入版本 ID 和必要的展示文本/哈希，确保提示词商城后续改名或切换默认版本不会影响历史记录。

### 4. 配置中心与生成选择器共享同一解析层

配置中心负责编辑和发布目录；主图/套图选择器只消费已发布配置，并保留现有工作台的受控组件接口。市场选择器从目录生成市场卡片，输出设置从模型能力计算可用分辨率，风格库从分组目录渲染，避免在组件内再维护第二份静态选项。

### 5. 先保留本地持久化边界，API 可替换

当前项目的 Zustand 状态已经使用 localStorage 持久化，第一阶段沿用相同的本地持久化方式，并把读写封装在配置仓储接口中。仓储接口的输入输出使用完整配置版本对象，后续接入后端时替换仓储实现，不改变页面和生成快照层。

### 6. 以槽位维度组织绑定界面

配置页面按“市场、模型、风格、主图模块、详情页模块”分区，每个条目旁展示当前绑定版本和编辑入口。风格绑定可细化到风格项；模块绑定必须覆盖内置模块 ID。这样用户能从目录直接理解绑定作用范围，也能避免一个全局提示词覆盖所有生成场景。

### 7. 模块数量属于项目生成草稿

模块目录仍为只读内置列表，模块选择和本次生成张数保存在项目级草稿的 `moduleCounts` 中，范围为 1 到 4。生成时按模块数量展开结果资产，快照记录每个模块的数量；数量变化只影响之后的生成。

## Risks / Trade-offs

- [Risk] 本地配置只在当前浏览器可见，跨设备同步能力有限 → 保留仓储接口并让配置版本结构可直接映射 API，后续接入服务端。
- [Risk] 用户删除了项目草稿正在使用的条目 → 生成前做 ID 有效性校验，明确提示重新选择，不静默切换生成语义。
- [Risk] 绑定槽位过多导致配置页面复杂 → 使用分区、搜索/折叠和“未绑定”状态摘要，首版保持单页可浏览。
- [Risk] 模型能力字段不完整会导致分辨率选择错误 → 模型保存时要求至少声明支持的分辨率集合，选择器只从该集合渲染。
- [Risk] 旧项目草稿只保存国内/国外聚合值 → 迁移到对应默认平台并保留历史快照中的原始市场对象。
- [Risk] 模块张数过大导致请求和结果过多 → 每个模块限制为 1–4 张，并在结果区按模块分组展示。

## Migration Plan

1. 用现有静态市场、模型、风格和内置模块生成初始已发布配置版本，并保留现有默认值。
2. 将当前工作台选择器切换为读取已发布配置；旧项目草稿中的 `domestic`、`international` 和旧模型/风格 ID 做一次兼容映射。
3. 为项目草稿增加 `moduleCounts`，缺失时所有已选模块默认 1 张。
4. 生成入口在提交时写入配置快照、提示词版本快照和模块张数。
5. 若需要回滚，停止读取新配置仓储，恢复静态目录解析；历史快照无需迁移。

## Open Questions

无。市场、模型和风格都允许 CRUD；主图/详情页模块仅允许提示词绑定的范围已确认。
