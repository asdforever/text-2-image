## Context

当前项目使用 React + Zustand + Vite，项目创建对话框在创建时只保存 `sourceCount`，并由 store 立即生成模拟原图资产。项目工作台由 `ProjectWorkbench` 组织，右侧面板内部已经使用 `react-resizable-panels`，但外层 `.workspace-content` 仍声明了一套独立的 Grid 分栏，造成重复宽度约束。全局样式主要集中在 `src/index.css`，页面目前以暗色值为默认，缺少统一的主题状态入口。

## Goals / Non-Goals

**Goals:**

- 让项目可以无素材创建，并在项目工作台内把实际文件添加到当前项目。
- 保证新增素材通过同一个项目 store 和资产模型进入资产库，刷新后仍归属于原项目。
- 提供全局亮暗主题切换、持久化选择，并覆盖工作台、弹窗和资产库。
- 让可调整面板成为工作台内容区域唯一的横向布局管理者，修复右侧空白和窄栏问题。
- 为文件编码检查、项目内上传、主题切换和布局回归提供可执行的测试入口。

**Non-Goals:**

- 本 change 不引入真实对象存储、后端上传 API 或图片处理服务；本阶段继续使用现有前端 mock/本地 URL 能力。
- 不重写已有的资产库、历史面板或套图业务，只补充它们所需的入口和状态同步。
- 不提供多用户同步主题、主题编辑器或第三种以上主题。

## Decisions

### 1. 将素材归属放入项目 store

新增 `addProjectAssets(projectId, files)` action，负责把通过校验的文件转换为 `Asset`，写入匹配项目的 `assets`，并更新项目时间。上传组件只负责选择文件、展示逐项校验状态和调用 action；不直接修改组件外部的项目对象。

选择该方案是因为项目 store 已经是项目和资产的持久化边界，能避免素材被错误写入全局或其他项目。替代方案是把文件状态留在工作台组件中，但刷新、资产库同步和跨 tab 定位都会产生重复状态。

文件阶段先限制为浏览器可读取的图片，复用 `accept="image/*"` 和大小校验；预览使用 `URL.createObjectURL`，组件卸载或替换文件时释放 URL。mock 环境下可以继续以对象 URL 作为 asset URL，未来接入上传 API 时只替换 action 内的 materialization 层。

### 2. 创建流程只校验基础信息，不校验素材数量

`ProjectCreateDialog` 第一步保留可选文件选择和预览，但“下一步”和最终创建按钮不依赖 `sourceCount > 0`。创建时传递已选文件（或先传递空数组），由 store 创建项目；当文件存在时沿用现有 mock 资产生成逻辑，空数组则生成空资产列表。项目工作台的空状态提供同一个上传入口。

这样可以保持旧的三步表单和快捷启动入口兼容，同时把“素材准备”从“项目身份创建”中解耦。不会通过删除第一步来改变用户对流程的理解。

### 3. 主题使用根节点属性加持久化状态

新增轻量 `useTheme`/主题 store，状态限定为 `light | dark`，初始化顺序为持久化值、系统 `prefers-color-scheme`、产品默认值。根组件在状态变化时设置 `<html data-theme="light|dark">`（必要时同步 class），主题按钮只调用切换 action，并设置 `aria-label` 和当前状态。

CSS 使用主题 token（背景、文本、边框、控件等）集中定义亮暗两组值，现有组件通过 token 引用；图片和业务状态颜色保留独立语义色。替代方案是给每个组件追加条件 class，但会导致弹窗、面板和新增页面遗漏主题。

### 4. 让可调整面板独占工作台横向布局

`.workspace-content` 改为 `display: flex` 或单列容器，仅负责撑满可用高度；`Group` 设置 `width: 100%; height: 100%; min-width: 0; min-height: 0`。删除外层固定 `grid-template-columns` 对右栏的约束，保留 `Panel` 的默认、最小和最大尺寸以及 `Separator` 手柄。右侧 `aside` 和 `.panel-body` 继续使用独立纵向滚动，不让布局容器承担第二条横向滚动。

该方案只保留一套宽度来源，直接对应截图中的空白列问题。替代方案是继续使用 CSS Grid 并移除 `Panel`，但会丢失现有的拖拽、折叠和尺寸状态能力。

### 5. 以行为测试覆盖回归边界

在现有 Node test 基础上增加 store/组件契约测试：空素材创建成功、项目内上传只更新目标项目、无效文件逐项失败、主题切换和持久化、布局关键 class/结构存在。编码检查脚本继续作为 `pretest` 和 `prebuild`，防止文档回归乱码。

## Risks / Trade-offs

- [本地对象 URL 在刷新后失效] → mock 阶段对刷新场景使用可持久化的 `/assets` 或 `/mock-assets` URL；真实上传接入时由上传层返回持久 URL，store 不保存 `File` 对象。
- [主题 token 覆盖不完整导致局部仍是暗色] → 为全局背景、文本、边框、表单、弹窗和工作台面板建立 token 清单，并在亮暗模式下执行桌面与窄窗口截图回归。
- [面板最小尺寸与窄窗口冲突] → 保留 `html/body/#root` 的最小宽度策略，同时为 `Group`、中心 Panel 和右 Panel 设置 `min-width: 0`，在最小支持宽度下验证折叠后的恢复入口。
- [旧项目已有 sourceCount 数据] → 读取旧数据时将缺失的 `assets` 视为空数组，保留已有资产；创建接口同时接受旧的 count 字段以避免破坏现有 mock 测试。

## Migration Plan

1. 先更新类型和 store action，再改创建对话框和工作台上传入口。
2. 引入主题状态和 token，默认保持当前暗色视觉，确认切换后再补亮色值。
3. 调整工作台容器约束并运行布局回归截图。
4. 执行编码检查、类型检查、单元/契约测试和生产构建。
5. 如需回滚，移除新增上传入口和主题控制，保留兼容的 `sourceCount` 创建参数；布局改动可独立回退，不影响资产数据结构。

## Open Questions

- 真实上传 API 接入时的文件大小、格式和对象存储字段仍由后续后端 change 定义；本 change 只固定前端校验反馈和项目归属行为。
