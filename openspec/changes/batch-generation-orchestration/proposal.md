## Why

阶段 3A 只能同步确认并生成一张主图。前端虽然已经允许为每个模块选择 1-4 张，但真实提交会被单张门禁拒绝，且页面刷新、Provider 失败或服务重启时无法可靠管理多张结果。

阶段 3B 需要把这条单张链路升级为可恢复的批次生成能力，真正兑现每个模块的图片数量选择，并让后续套图和画布共享任务编排基础。

## What Changes

- 新增持久化的主图生成批次、模块任务、图片槽位和尝试记录；一个模块按用户选择创建 1-4 个槽位。
- 将多模块的视觉提示词编译、集中确认和入队执行与阶段 3A 单张同步确认路径分离。
- 新增数据库驱动 Worker、租约、可恢复的领取规则、受控取消和仅失败槽位重试。
- 主图工作台改为展示批次、模块和单张槽位状态，允许实际选择每个模块的生成张数，并保留成功图片。
- 保持冻结的源图、已发布配置、提示词版本和约束卡快照；历史阶段 3A 任务及其资产不被迁移或改写。

## Capabilities

### New Capabilities
- `batch-generation-orchestration`: 为主图创建、确认、执行、恢复、取消和重试多模块多图片槽位批次的持久化生成编排。

### Modified Capabilities
- 无。

## Impact

- 后端增加批次编排领域模型、Alembic 迁移、仓储、Worker、调度 API 和状态读取接口；复用阶段 3A 的视觉提示词编译、约束卡、图片 Provider 和项目资产服务。
- 前端替换阶段 3A 的单模块单张门禁与同步确认路径，保留模块数量控件并将其连接到真实批次结果。
- 新增 Worker 启动、租约恢复、Provider 并发上限和批次级幂等配置；真实图片调用继续只发生在用户确认后的已领取槽位。
