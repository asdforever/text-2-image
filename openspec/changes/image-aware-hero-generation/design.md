## Context

当前项目已具备项目资产域、受控对象存储、单用户工作区身份、持久化幂等和已发布生成配置解析；主图页面仍调用本地 `mockGenerateHeroImage`。参考工程表明已配置的 `gpt-image-2` 图生图能力使用 `/v1/images/edits` 的 multipart 文件上传，而图像感知提示词使用独立多模态模型读取产品视觉输入。

见 `proposal.md` 了解动机，见本变更规格了解对外行为。

## Goals / Non-Goals

**Goals:**

- 实现“视觉提示词编译、用户确认或编辑、单张主图生成”的明确工作流。
- 将平台和全局风格作为服务端锁定、确定性组合的约束卡。
- 用新任务记录承载快照和状态，再复用项目资产域保存成功图片。
- 保持 Provider、提示词编译、存储和任务协调彼此独立，方便阶段 3B 扩展。

**Non-Goals:**

- 不实现批量、队列、Worker、取消、独立重试、租约或进程重启恢复。
- 不允许编辑平台、风格、真实性约束、源图或已发布配置选择；只允许在生成前编辑实时任务提示词。
- 不生成套图或视频，不修改已有历史资产。
- 不持久化 API 密钥、授权头、预签名 URL 或 Provider 原始错误响应。

## Decisions

### 1. 采用“任务先落库、确认后同步执行”的最小生命周期

创建 `compiling_prompt -> awaiting_confirmation -> generating -> succeeded | failed` 的主图生成任务。编译请求创建任务并同步调用多模态模型，成功后返回待确认任务；确认请求可携带经过用户编辑的实时任务提示词，并在同一请求内调用图片 Provider。前端分别展示编译、待确认和生成中状态；任务查询接口保留为刷新或网络中断后的恢复边界。

这使用户能在付款调用前检查任务提示词，同时保持第一张真实图的可追溯状态，且不引入 3B 的队列协调。一次提交立即生图不提供检查边界；仅返回异步任务 ID 的方案更适合 Worker，但会超出当前切片。

### 2. 视觉编译只生成任务段，平台和风格由服务端确定性组合

提示词分为四层，按以下固定顺序组合：商品真实性约束、具体电商平台约束卡、全局风格约束卡、确认后的实时任务提示词。平台卡优先取已发布绑定提示词版本中非空的 `user_prompt_template`，未提供运行时内容时回退市场 `guidance`；风格卡同样优先取绑定版本的 `user_prompt_template`，否则回退风格 `description`。提示词版本的长篇 `body` 不会作为平台或风格约束全文拼入最终提示词。这些卡片的原文、来源和哈希写入快照。

多模态编译模型只接收源图、主图模块说明、模块补充参数和自定义风格，输出 JSON：`taskPrompt`、`visibleFacts`、`unconfirmedItems`。主图模块已绑定提示词版本的 `body` 作为专业提示词规划师的系统指令，`user_prompt_template` 用于渲染结构化任务输入；未绑定时使用服务端内置编译系统指令和模块目录说明。系统指令要求它不输出或改写平台/全局风格规则，也不把不可见或未确认的信息写为事实。所用系统指令、模板版本和内容哈希全部写入任务快照。

将所有提示词全文交给编译模型再拼接会造成规则漂移；先生成一条完整提示词再让第二个模型改写会增加成本和随机性。这两个方案均不采用。

### 3. 以两个明确的 Provider port 区分视觉理解与图生图

新增多模态提示词编译 port，使用 `CONTEXT_BASE_URL`、`CONTEXT_API_KEY`、`CONTEXT_MODEL` 和 `CONTEXT_TIMEOUT_MS`；请求通过 OpenAI 兼容聊天接口将源图作为 data URL 图片内容发送。新增图片编辑 port，使用既有 `IMAGE_GENERATION_*` 设置，向 `/v1/images/edits` 发送 `multipart/form-data`：`model`、单个 `image` 文件、最终 `prompt`、映射后的 `size`、`quality`、固定 `n=1` 和 `response_format=b64_json`。

图片模型调用绝不使用旧 `TestExecutor`：它属于提示词测试域并耦合 `TestRun`、产品库和其他对象 key。Provider 只返回已校验的图片字节和 MIME 类型；上游临时 URL、错误正文与鉴权信息不会跨出适配器。

### 4. 分辨率映射由服务端 Provider policy 控制

浏览器提交已发布模型支持列表中的分辨率标签和比例。服务端根据当前第一个 Provider 的受支持组合解析本机 `size`、`quality`；无映射的组合在调用前以稳定错误拒绝。任务快照同时保存用户选择和实际 Provider 参数。

当前生成配置模型目录只保存展示分辨率，没有通用的厂商参数映射；将 Provider 原生字段暴露给浏览器会把厂商协议泄漏进业务配置。阶段 3A 采用受控的 `gpt-image-2` 映射表，阶段 3B/后续多 Provider 扩展再使映射成为配置模型的一部分。

### 5. 新任务表保存生成来历，生成图片继续使用项目资产域

新增 `project_workbench.hero_generation_tasks`，记录项目、源资产、状态、编译和确认幂等键、不可变 JSON 快照、原始编译提示词、确认后的任务提示词、最终提示词及哈希、错误码/安全错误消息、生成资产 ID 和时间戳。以工作区及对应操作的幂等键约束防止重复编译或重复真实请求。

成功时，图片先写入项目专属对象 key，校验尺寸/MIME/哈希，再创建对象记录和 `kind=generated` 的项目资产；生成资产设置 `source_asset_id` 与任务 ID 作为 `generation_snapshot_id`。数据库写入失败后删除刚上传的对象；失败任务不创建生成资产。该设计复用既有预览、删除和源资产引用保护，不创建第二套结果存储模型。

### 6. 前端仅传选择和补充参数，并改用真实结果

`HeroImageWorkspace` 将单模块、单张路径切换为“编译”和“确认生图”两个项目 API。前端不传配置正文、工作区、存储 key、Provider URL 或密钥；在确认阶段只能传回用户编辑后的实时任务提示词。后端通过当前身份、已冻结的编译任务快照和提示词仓储解析最终请求。3A 只允许选择一个模块和一张结果，现有多模块/模块张数交互属于 3B 的遗留显示态，必须在真实提交路径中被门禁。

成功响应中的任务摘要提供最终提示词和可安全展示的快照摘要；图片预览继续走项目资产预览路由。失败只展示服务端稳定错误消息，不能覆盖已有结果。

## Risks / Trade-offs

- [风险] 多模态模型可能从图像中臆测商品事实 -> 缓解：固定系统提示词、结构化 `unconfirmedItems`、只把可见或用户明确输入的事实写入任务段。
- [风险] 编译后用户迟迟不确认 -> 缓解：保留待确认任务但不调用图片 Provider；过期清理策略留给后续阶段。
- [风险] 确认后的同步图片请求可能较长 -> 缓解：前端明确运行态、超时错误和可查询任务；异步 Worker 留给 3B。
- [风险] 当前环境未配置视觉编译模型 -> 缓解：启动不失败，但提交时返回明确的 `PROMPT_COMPILER_UNAVAILABLE`，并在 `.env.example` 说明所需变量。
- [风险] Provider 尺寸能力与目录展示值漂移 -> 缓解：服务端映射、提交前验证和参数快照；未知组合不降级。
- [风险] 对象上传成功但数据库提交失败 -> 缓解：捕获异常后删除新对象，删除失败时记录待清理状态。

## Migration Plan

1. 新增运行配置、任务表、索引和 Alembic 前向迁移；不修改现有项目资产记录。
2. 部署 Provider/编译器适配器与任务 API，未配置编译模型时仅新生成受控失败，已有项目与结果不受影响。
3. 将主图工作台单模块单张提交切换到提示词编译与确认生图 API，保留历史浏览器草稿的显示但不作为真实生成输入。
4. 回滚时先撤回前端提交入口和路由流量，保留任务和生成资产历史；生产业务数据库不执行 downgrade。
