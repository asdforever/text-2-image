## Why

主图工作台仍以浏览器模拟生成，无法利用产品图的视觉信息，也无法将一次真实生图的提示词、配置、结果和失败状态可靠地保存下来。阶段 3A 需要交付第一张可在前端验收的真实主图，同时保证平台和全局风格规则不会被提示词编译模型改写。

## What Changes

- 新增项目主图的单任务、单结果真实生成能力：一个源图、一个主图模块、一次确认只生成一张图片。
- 接入多模态提示词编译：它根据产品图、主图模块和用户补充参数生成当前图片专属提示词，并返回可见事实与无法确认项；用户确认或编辑任务提示词后才会生图。
- 将已发布配置中的具体电商平台规则和图片风格规则作为不可变约束卡，由服务端按固定顺序与实时任务提示词组合；不让编译模型改写这些卡片。
- 接入 OpenAI 兼容的 `gpt-image-2` 图生图 Provider，使用 `/v1/images/edits` 的 multipart 文件上传协议，而非将源图 URL 放入文生图 JSON 请求。
- 持久化生成任务、输入/约束/提示词/Provider 请求快照、状态和生成结果；成功结果创建 `generated` 项目资产，失败保留可读且不含密钥的错误。
- 主图工作台改为先展示待确认提示词，再调用真实生成接口，展示运行中、成功图片与失败状态；本阶段不支持批量或独立重试。

## Capabilities

### New Capabilities

- `image-aware-hero-generation`: 使用产品视觉输入和已发布配置生成、保存并展示单张真实主图。

### Modified Capabilities

- 无。

## Impact

- 后端新增生成任务域、迁移、仓储、应用服务、Provider 与多模态提示词编译适配器，以及项目主图生成 API。
- 扩展后端运行配置以安全读取多模态提示词编译模型的服务地址、密钥、模型和超时；密钥不会出现在 HTTP 响应、日志或数据库快照中。
- 前端主图工作台从本地 `mockGenerateHeroImage` 切换到真实 API，并将服务端生成资产显示为项目结果。
- 复用项目资产域、对象存储、服务端身份、幂等机制、提示词版本仓储和已发布生成配置解析；阶段 3B 及阶段 5 的队列编排和画布持久化不在范围内。
