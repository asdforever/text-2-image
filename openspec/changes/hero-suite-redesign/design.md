## Context

参见 `proposal.md` 的问题与范围说明。当前项目使用 React、TypeScript、Vite、Zustand 和自定义 CSS：`ProjectWorkbench` 已有项目级输出类型导航，主图生成仍由 `HeroConfigDialog` 收集参数，`HeroImageWorkspace` 主要负责结果网格，详情图则在 `SuiteConfigPanel` 与 `SuiteCanvasView` 之间切换。现有主题通过语义 CSS 变量支持明暗模式。

本次视觉基准为仓库中的 `workbench-reference-v1.svg` 以及用户提供的主图、详情图长图。参考图的关键不是固定页面高度，而是左侧高密度长配置、右侧持续可见的结果区和清晰的卡片层级。

## Goals / Non-Goals

**Goals:**

- 用一套共享骨架承载主图和详情图，减少两套工作台的结构漂移。
- 在 1440×960 和 1280×720 桌面视口中保持配置与结果同时可用。
- 完整覆盖参考长图中的配置要素，不因首屏高度删除功能。
- 将草稿、校验、生成状态和局部失败处理设计成可测试的明确状态。
- 复用项目现有素材与任务数据，不破坏已有生成结果。

**Non-Goals:**

- 不新增或修改后端 API。
- 不重构白底图和视频工作台的业务内容。
- 不引入新的 UI 框架、表单框架或拖拽面板依赖。
- 不在本次实现风格库管理后台、用户自定义风格或多人协作。
- 不保证小于 1024px 的完整双栏体验；该尺寸使用配置抽屉或单栏降级。

## Decisions

### Decision 1: 保留项目级输出类型导航

**选择：** 保留 `ProjectWorkbench` 顶部的白底图、主图、详情图和视频导航，当前工作台只负责模式内部的配置与结果。

**理由：** 用户需要在同一项目的输出类型之间快速切换，参考 SVG 也已确认顶部模式切换。删除顶部导航会迫使全局工具栏承担业务模式切换，并与当前代码和最新视觉方向冲突。

**备选方案：** 只使用左侧图标工具栏。该方案节省少量垂直空间，但标签语义和当前项目上下文不够清晰，因此不采用。

### Decision 2: 共享双栏骨架与弹性左栏

**选择：** 创建共享工作台布局，桌面端使用 CSS Grid：

```css
.generation-workspace {
  display: grid;
  grid-template-columns: clamp(360px, 28vw, 408px) minmax(0, 1fr);
  min-width: 0;
  min-height: 0;
}
```

在 1440px 参考视口中，左栏目标宽度约 392px。左栏和右栏各自拥有滚动容器；页面外层不承担业务内容滚动。

**理由：** 固定 360px 无法舒适容纳双列模块卡片和完整风格描述，纯百分比宽度又会在不同视口产生过大波动。`clamp` 能保留参考图比例并限制极值。

**备选方案：** 引入可拖拽分栏。该能力不属于核心生成流程，还会增加状态和键盘交互成本，因此不采用。

### Decision 3: 长配置内容与固定生成区分离

**选择：** 配置面板分为 `scroll body` 和 `sticky footer`。历史配置、素材、文本、风格和模块目录位于可滚动内容区；选择计数、校验摘要和主生成按钮位于固定底部区。

**理由：** 参考长图包含大量配置要素，真实桌面视口不可能同时展示全部内容。独立滚动保留完整能力，同时使关键操作始终可达。

**备选方案：** 将生成按钮放在长面板末尾。该方案实现简单，但用户需要反复滚动才能确认选择并提交，因此不采用。

### Decision 4: 采用业务中等粒度的共享组件

**选择：** 共享布局与重复业务块，页面组合模式专属区块：

- `GenerationWorkspaceLayout`：双栏、收起左栏、滚动边界。
- `ConfigPanelContainer` 与 `ConfigSectionCard`：长面板和卡片层级。
- `RecentConfigCard`：最近配置摘要与恢复。
- `ProductAssetPicker`：上传、素材库选择、缩略图和数量限制。
- `CountedPromptField`：设计简报、专业创作指令和促销信息。
- `OutputSettings`：语言、模型、宽高比和分辨率。
- `MarketSelector`、`StyleLibrary`、`ModuleSelector`：市场、分类风格和模块目录。
- `GenerationFooter`：计数、校验反馈和主操作。
- `ResultModeTabs` 与结果状态组件：图片、富文本和内测入口。

主图和详情图页面负责字段组合、模式约束与生成动作，不把业务差异塞入大量布尔属性。

**理由：** 业务中等粒度组件可复用视觉和交互，又能保持主图与详情图配置结构清晰。原子控件继续使用现有 `components/ui`。

**备选方案：** 创建一个包含所有字段的巨大配置组件。该方案初期文件少，但条件分支会随两种模式快速膨胀，因此不采用。

### Decision 5: 草稿按项目和模式隔离

**选择：** 在现有 Zustand store 中按 `projectId + mode` 保存主图和详情图草稿；组件使用受控值更新草稿。最近配置卡片读取同一份持久化草稿元数据。生成结果仍使用项目现有资产/任务集合。

建议的数据边界：

```ts
type CommonGenerationConfig = {
  selectedAssetIds: string[];
  outputLanguage: string;
  market: "domestic" | "international";
  model: string;
  aspectRatio: string;
  resolution: string;
  styleId: string | null;
  selectedModuleIds: string[];
};

type HeroGenerationConfig = CommonGenerationConfig & {
  designBrief: string;
  promotion: string;
};

type SuiteGenerationConfig = CommonGenerationConfig & {
  creativePrompt: string;
};
```

**理由：** 页面切换时本地组件 state 会丢失，单个全局 config 又会使两个模式互相覆盖。按项目和模式隔离既支持恢复，又无需后端迁移。

**备选方案：** 仅保存在页面 state。该方案无法满足切换模式后恢复草稿的规格，因此不采用。

### Decision 6: 风格与模块使用静态类型化目录

**选择：** 将风格分类、市场适用性和两套模块目录放在 TypeScript 常量中。风格目录至少包含基础风格、科技数码、居家生活、自然清新、品质奢华、潮流文化和人群主题；模块目录分别包含主图 8 项和详情图 18 项。

每个条目包含稳定 ID、显示名称、简述、适用模式和排序。详情图选择上限为 5，主图选择范围为 1–8。

**理由：** 当前目录属于版本化产品预设，不需要远程管理。类型化常量方便校验重复 ID、模式归属、顺序和文案完整性。

**备选方案：** 从后端动态获取。当前没有相应 API，且会扩大本次范围，因此不采用。

### Decision 7: 两种生成流程使用显式状态机

**选择：** 两种模式共享 `idle → validating → generating → completed | partial | failed` 状态；详情图在验证后增加 `planning → planned`，由用户确认规划后进入图片生成。

- 主图：有效配置直接为所选模块创建图片生成任务。
- 详情图：先为 1–5 个模块生成独立规划项，允许单项编辑，再生成图片。
- 局部失败不清空成功项，失败项可单独重试。

**理由：** 显式状态能避免空状态、加载态和结果态互相覆盖，也便于测试按钮禁用、进度和错误恢复。

**备选方案：** 使用单个 `isLoading` 布尔值。它无法表达规划完成、部分失败和单项重试，因此不采用。

### Decision 8: 右侧采用模式化结果呈现

**选择：** 右侧共享标题、说明、结果类型标签、收起左栏和状态区域；内容呈现按模式区分：

- 主图使用聚焦预览加自适应结果网格，窄宽度时单列，空间足够时扩展为多列。
- 详情图使用按详情页顺序排列的纵向模块列表，规划内容与图片结果在同一模块卡片中演进。

**理由：** 主图需要横向比较候选方案，详情图更依赖上下叙事顺序。强行统一为同一种结果布局会削弱两种任务各自的核心体验。

### Decision 9: 使用现有主题变量实现参考视觉

**选择：** 新组件只使用语义色彩、间距、圆角和阴影变量。亮色主题映射为参考稿的浅灰背景、白色卡片、细灰边框和黑色主按钮；暗色主题继承现有全局变量，不在组件内硬编码另一套颜色。

**理由：** 这样可以精确落地参考图，同时不破坏项目已有的主题切换能力。

## Validation and Error Handling

- 字段错误就近显示；固定底部区提供汇总，但不使用只在 toast 中出现的唯一错误说明。
- 不支持的文件、上传失败、数量超限分别显示明确原因，并保留已成功素材。
- 必填校验在创建任务前执行：主图需要至少一张素材和一个模块；详情图需要至少一张素材和 1–5 个模块。
- 参数组合不兼容时禁用不可用选项，并保留最近一个有效组合。
- 生成失败按模块记录；重试仅提交失败模块，不重复生成成功模块。
- 删除生成结果沿用项目现有确认与资产删除行为。

## Testing Strategy

- 数据目录测试：模块数量、稳定 ID、无重复 ID、模式归属、详情图最多选择 5 项。
- 共享组件测试：独立滚动、固定操作区、字数限制、素材数量限制、折叠状态、参数联动和键盘操作。
- 页面集成测试：草稿按项目/模式隔离，顶部导航切换不丢失草稿，主图直接生成，详情图规划后生成。
- 失败路径测试：上传失败、不兼容参数、部分模块失败、单项重试和整套导出。
- Playwright 测试：1440×960 与 1280×720 无横向页面滚动，左侧与右侧可独立滚动，主操作始终可达。
- 视觉回归：亮色主题与 `workbench-reference-v1.svg` 的布局层级、间距和关键状态一致；暗色主题保证可读性而不要求像素级复刻。

## Risks / Trade-offs

- **[左栏信息仍然较密]** → 默认展开核心区块，风格库与高级设置允许折叠，并保持固定生成区。
- **[共享组件被模式条件污染]** → 共享组件只接收数据和受控状态，字段组合与约束留在模式页面。
- **[草稿结构升级导致旧数据不完整]** → 为新增字段提供默认值并在读取时归一化，不要求持久化数据迁移。
- **[详情图两阶段流程增加操作一步]** → 规划完成后提供明确的批量生成入口，同时允许用户先修订单个模块，避免直接生成大量错误图片。
- **[移除画布影响已有入口]** → 先完成列表流程和回归测试，再移除当前路由中的画布引用；仅在全仓无引用时移除相关依赖。
- **[亮色参考与暗色默认存在差异]** → 使用语义变量，并把参考视觉验收固定在亮色主题。

## Migration Plan

1. 先添加类型化风格/模块目录、草稿类型和共享配置组件，不改变现有路由。
2. 为主图接入共享双栏骨架，在结果区复用现有资产网格；验证后移除 `HeroConfigDialog` 入口和状态。
3. 为详情图接入同一骨架，实现规划列表和模块结果；验证后替换 `SuiteConfigPanel`/`SuiteCanvasView` 的模式切换。
4. 将顶部输出类型导航保留并统一标签名称为白底图、主图、详情图和视频。
5. 全仓检查画布组件与依赖引用；仅在没有其他消费者时删除不再使用的代码或依赖。
6. 运行单元、集成、端到端、视觉和构建验证后移除迁移期兼容代码。

回滚时恢复原页面组合和对话框入口即可；新草稿字段只增加前端状态，不改变已有资产数据，因此不需要数据库回滚。
