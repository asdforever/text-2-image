## Why

工作台当前已经能够上传项目素材、生成图片并提供图片编辑界面，但编辑会话、OCR、操作历史和正式成品之间还没有统一的后端持久化边界。直接上传的素材应继续只属于当前项目，只有用户确认的可交付版本才进入正式产品库，避免临时素材和测试结果污染可复用成品。

## What Changes

- 新增图片编辑会话，保存编辑草稿、操作记录、OCR 结果和提交状态。
- 新增编辑任务、生成尝试和图片版本链路，支持重试、再次生成和当前版本/终版选择。
- 新增正式产品库成品模型，支持主图、详情页套图、白底图、场景图和编辑后的产品版本。
- 正式产品成品保存项目、任务、任务版本、生成批次、源图版本、提示词快照和生成配置快照等来源信息。
- 明确项目素材、全局素材库、提示词测试产物库和正式产品库的边界；工作台直接上传不自动写入全局素材库。
- 提供从编辑结果发布/关联到正式产品库的接口，并保留版本和对象存储生命周期。

## Capabilities

### New Capabilities

- `image-editing-sessions`: 管理图片编辑会话、操作历史、OCR、编辑任务、生成尝试和图片版本。
- `product-library`: 管理正式产品成品、版本关系、来源追溯、发布和归档。

### Modified Capabilities

无。现有项目素材上传仍保持项目内归属，不自动进入全局素材库；提示词测试产物库继续独立存在。

## Impact

- 后端新增图片编辑领域模型、仓储、服务和 API 路由，复用现有图片编辑 Provider 端口但不在工作台接口中直接调用 Provider。
- 扩展现有对象存储和项目资产引用，保证编辑版本可追溯且删除时遵循引用计数和待清理机制。
- 前端现有图片编辑器和产品库 API 边界接入持久化接口，替换仅依赖浏览器状态的编辑草稿。
- 新增数据库迁移、契约测试、服务测试和受控图片编辑流程测试；不接入真实计费或外部生产 Provider。
